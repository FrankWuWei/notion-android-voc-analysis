- 狀態：已通過實作前設計審查。
- 內容依據：`docs/portfolio_web_content_spec_v1.md`。
- 視覺依據：`docs/portfolio_web_visual_spec_v1.md`。

## Subject

這不是一份評論 Dashboard，而是一個「如何把雜亂使用者回饋轉為可重跑、可驗證分析流程」的技術案例研究。核心是分析決策、來源追查與解讀邊界。

## Audience

- 主要：AI 應用與系統整合職缺的面試官或用人主管。
- 次要：資料分析與產品分析職缺的面試官。

讀者需要快速判斷：分析流程是否真正落地、AI 輸出是否有品質控制、結果是否能回到來源，以及作者是否知道哪些結論不能推論。

## Single job

第一屏唯一任務是讓讀者理解：本專案把 6,186 則有效評論轉為可重跑、可驗證的使用者回饋分析流程。

第一屏不要求點擊 CTA，也不提前呈現批次數、主題數或 evidence 數。

## Tokens

### Color roles

- Canvas：`#F4F1EA`。
- Surface：`#FAF8F3`。
- Text：`#18211E`。
- Accent：`#2F6B5F`。
- Dark technical section：`#13211D`。
- Caution：`#8A571D`。

### Type roles

- 中文標題與正文：`Noto Sans TC`。
- 英文與數字：`Instrument Sans`。
- 技術 metadata：系統等寬字體。

### Spacing rhythm

- 基準：`8px`。
- 桌面區段上下間距：`120–136px`。
- 手機區段上下間距：`72–80px`。

### Radius logic

- 一般內容不使用卡片，因此不依賴圓角建立層級。
- evidence 展開與品質比較面板使用小幅圓角，預設不超過 `8px`。
- 按鈕不使用膠囊形狀。

### Elevation rule

- 主要層級由留白、分隔線與明暗背景建立。
- 一般區段不使用陰影。
- 手機固定導覽只允許一條細分隔線，不使用浮動卡片陰影。

## Layout concept

採用「不對稱編輯式技術案例研究」：桌面左側為低存在感章節導覽，右側為連續敘事；一般正文維持窄閱讀寬度，資料流、品質比較與主題證據可以擴展到完整內容寬度。

## Signature element

唯一主要記憶點是深色品質控制案例：並列模型原始輸出與真實來源評論，讓「引文可回查仍可能語意錯誤」成為可直接看懂的工程判斷。

19 格批次覆蓋條只承載分析資訊，不作為第二個視覺噱頭。

## Generic-default critique

本設計避免常見作品集與 AI 專案模板：

- 不使用置中的巨大 Hero 與雙 CTA。
- 不使用 KPI 卡片牆、技術 Logo 牆或 Dashboard 網格。
- 不使用抽象 AI 圖像、霓虹漸層、裝置 Mockup 或聊天泡泡。
- 不用動畫製造工程成果感。
- 不用大量元件外框切碎長篇案例敘事。

辨識度來自資料流、來源比較、批次覆蓋與克制的解讀邊界。

## UI copy review

- 公開頁面以「分析流程」取代第一層的 `Pipeline`。
- evidence 控制使用「查看來源／收合來源」，描述讀者意圖。
- 資料缺少時使用「資料未提供」，不留白或推測。
- 延伸驗證使用「資料不足以支持結論」，不使用錯誤警報語氣。
- 不使用「可以回答／不能回答」或「不再次呼叫 API」作為標題。
- 不放置尚未啟用的「查看原始碼」或「下載資料」按鈕。

## Rejected alternatives

- 全站深色：不利長篇閱讀。
- 三欄卡片式案例頁：容易形成模板感。
- 完整 evidence Dashboard：超出第一版作品集的核心任務。
- Tailwind／shadcn 元件堆疊：不符合連續編輯式版面需求。
- Inter：過於常見，英文與數字改用 `Instrument Sans`。
- 大量進場動畫：與可驗證、克制可信的內容定位不符。

## 已確認補強：延伸驗證案例

- 延伸驗證區加入一個由正式分析表產生的真實前後比較案例。
- 使用比較表、案例判定與來源展開，不加入折線圖或新的 KPI 卡片群。
- 數字下降與「資料不足」判定同時出現，避免形成改善成效暗示。
- 此案例用來證明驗證設計與解讀邊界，不成為第二個主視覺記憶點。
