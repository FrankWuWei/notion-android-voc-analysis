# Notion Android VOC 作品集 Dashboard 設計

## 目標

建立一個可在面試中展示的靜態 React dashboard，讓閱讀者在數分鐘內理解本專案
如何從 Google Play 評論蒐集資料、執行情緒與 LLM 主題分析，並以公開產品更新
建立保守且可追溯的觀察結論。

## 使用者與主要判斷

主要讀者是資料分析、AI 應用或產品相關職缺的面試官與教師。第一屏必須讓讀者
判斷：此專案是否有完整資料 pipeline、能否清楚表達分析限制，以及能否由結論
回查到評論證據。

## 視覺方向：Analysis Fieldbook

採資料研究筆記與控制台的混合版面，而非行銷型 landing page。頁面使用明亮灰白
底色、墨黑文字、藍綠色資訊重點與珊瑚紅色警示重點。主要資訊由細格線、時間
刻度、表格與標籤組成，形成「可審閱的分析紀錄」感。

### 設計 Tokens

- `--canvas: #F3F7F8`：主要背景。
- `--surface: #FFFFFF`：資料表與工具區表面。
- `--ink: #172126`：主文字與深色結構。
- `--muted: #627078`：次要說明文字。
- `--teal: #007C78`：流程、正向資訊與可用狀態。
- `--coral: #D85B45`：負面評論與需留意的資訊。
- 顯示字體使用 `DM Mono`，內文使用 `Manrope`。
- 間距採 8px 節奏；工具面板與資料卡採 6px 圓角。
- 僅使用 1px 邊框與低對比陰影，不堆疊卡片。

## 版面與內容

1. **摘要列**：專案名稱、資料期間、6,186 則評論、3 個 sentiment buckets、5 個
   更新前後案例。
2. **Pipeline 軌跡**：依序顯示評論蒐集、語意保留清洗、sentiment-analysis、LLM
   主題萃取、公開更新脈絡與前後觀察。
3. **結果儀表板**：以 5 個代表案例的更新前後提及率、狀態與變化百分點為主。
4. **主題詳情工具區**：選擇任一主題後，顯示更新日期、更新名稱、觀察解讀、
   片語規則與更新前後的證據列。
5. **方法與限制**：明確呈現 `general_product_release`、規則式比對、28 天窗口，
   以及不將結果解釋為 Android 修復的原因。

## 互動

- 點選趨勢列或主題標籤即可切換詳情與證據。
- 使用狀態篩選，聚焦 `limited_post_evidence` 或 `not_observed_after_release`。
- 證據列可依更新前／更新後切換。
- 不提供上傳、重新訓練或 API 呼叫，維持作品集展示範圍。

## 資料

前端讀取已生成的靜態 JSON，內容由目前的趨勢表、摘要、證據表及 pipeline 描述
組成。這份 JSON 是展示用資料快照；來源檔仍保留在 `data/` 與 `outputs/`。

## 成功條件

- 桌面與手機版皆可閱讀且可操作。
- 首屏可辨識資料規模、流程和核心觀察。
- 五個案例與 19 筆證據可在介面中查看。
- 所有文案保持繁體中文，技術欄位與狀態值保留原始英文。
- 不使用「已修復」或「未修復」等超出資料支持範圍的結論。
