# Notion Android 使用者回饋分析作品集：視覺規格 v1

## 文件狀態

- 狀態：視覺方向、十個區段、設計 token、響應式版面與互動均已實作並驗證。
- 內容依據：`docs/portfolio_web_content_spec_v1.md`。
- 用途：作為新版作品集網站的版面、視覺、響應式與互動依據。
- 明確排除：不參考舊網頁的版型、配色、元件、截圖、動畫或設計稿。

## 整體定位

新版網站採用「技術案例研究型」而不是資料儀表板或 AI 產品宣傳頁。

視覺應傳達：

- 工程判斷清楚。
- 資料與證據可追溯。
- 分析結論克制可信。
- 長篇內容容易閱讀。
- 技術細節存在，但不壓過主要敘事。

## 明暗基調

採用「淺色主體＋深色技術區段」。

- 一般敘事與長篇正文使用偏暖白或極淺灰背景。
- 技術流程、品質控制案例等需要聚焦的工程內容，可使用深墨色背景。
- 不使用全站深色，避免長文閱讀疲勞與儀表板感。
- 不使用全站純白，保留編輯式案例研究的層次。

## 色彩方向

主色採用低彩度墨綠／青綠。

- 主要背景：偏暖白或極淺灰。
- 主要文字：深炭黑。
- 深色區段：深墨色。
- 主要強調色：低彩度青綠，用於資料流、目前章節、可追溯狀態與關鍵連結。
- 警示與限制：少量琥珀色。
- 痛點、正向價值與限制不可只靠紅、綠、黃區分。
- 不使用大面積漸層、霓虹光暈或高飽和 AI 常見配色。

初步色彩 token：

- 頁面背景：`#F4F1EA`。
- 內容底色：`#FAF8F3`。
- 主要文字：`#18211E`。
- 次要文字：`#5E6964`。
- 分隔線：`#CED5D0`。
- 主強調色：`#2F6B5F`。
- 淡強調底色：`#DCEAE5`。
- 品質案例深色背景：`#13211D`。
- 深色區主要文字：`#F4F1EA`。
- 深色區次要文字：`#B9C7C1`。
- 限制提示：`#8A571D`。
- 限制提示底色：`#F1E3CF`。

實際前景／背景對比度已完成檢查，主要文字、次要文字、強調色、深色區文字與限制提示皆符合 WCAG AA 一般文字門檻。

## 字體方向

採用「無襯線內容＋等寬技術資訊」。

- 中文標題與正文使用清楚的無襯線字體。
- 英文 evidence 以易讀無襯線字體為主。
- `review_id`、分析批次、模型名稱、欄位值與技術 metadata 使用等寬字體。
- 不使用過細字重。
- 不為了塞入資訊而縮小內文與輔助文字。
- 中英文混排必須檢查基線、字重與標點呈現。

字體家族：

- 中文標題與正文：`Noto Sans TC`。
- 英文與數字：`Instrument Sans`。
- 技術 metadata：系統等寬字體，以 `Consolas` 為 Windows 優先選項，不額外下載第三套字體。

初步字級：

- 第一屏主標題：桌面 `56–64px`，手機 `38–42px`。
- 區段標題：桌面 `36–40px`，手機 `28–32px`。
- 正文：桌面 `18px`，手機 `17px`。
- 英文 evidence：`18–20px`。
- 技術 metadata：`13–14px`。

## 整體版面

採用中等偏寬鬆的編輯式節奏。

- 一般正文維持適合長文閱讀的中等寬度。
- 流程圖、品質比較與主題結果可以突破正文寬度。
- 區段之間使用明顯留白、細分隔線或背景明暗切換。
- 同一畫面不塞入過多指標、標籤或小卡片。
- 主標題具有足夠層級，但不使用占滿整個首屏的巨大字級。
- evidence 引文維持正常閱讀尺寸，不作為小字註解。

尺寸與斷點：

- 桌面：`1200px` 以上，顯示左側固定章節導覽。
- 平板：`768–1199px`，改用頂部章節導覽。
- 手機：`767px` 以下，內容改為單欄。
- 整體頁面最大寬度：`1440px`。
- 左側導覽寬度：`180px`。
- 導覽與內容間距：`48–56px`。
- 主要內容最大寬度：`1040px`。
- 一般正文閱讀寬度：`680–720px`。
- 第一屏左右比例：約 `62% / 38%`。
- 桌面區段上下間距：`120–136px`。
- 手機左右頁邊距：`20px`。
- 手機區段上下間距：`72–80px`。
- 全站以 `8px` 為間距基準。

## 章節導覽

十個內容區段在導覽中整理為五個章節：

1. 專案概覽。
2. 分析方法。
3. 品質驗證。
4. 分析發現。
5. 工程交付。

桌面版：

- 左側固定章節導覽。
- 捲動時標記目前章節。
- 主內容保留穩定閱讀寬度。
- 導覽顯示五個章節編號與名稱；目前章節使用墨青綠文字與短線標記。
- 點擊章節後移動至對應內容，網址同步保留章節錨點。
- 不加入閱讀百分比或裝飾性進度環。

手機版：

- 導覽收合為約 `52px` 高的頂部固定「章節」列。
- 固定列顯示目前章節，選單在導覽列下方展開，不使用全螢幕選單。
- 選擇章節後立即收合。
- 導覽背景使用實色暖灰白，不使用透明模糊效果。
- 不在頂部塞入全部十個區段名稱。

## 內容容器原則

使用「連續案例敘事＋少量重點面板」。

- 一般背景、方法與限制說明不使用卡片。
- 三項技術決策使用編號段落，不做三張相同卡片。
- 品質控制案例使用明確比較面板。
- evidence 使用引用樣式，不使用聊天泡泡。
- 不建立大量巢狀卡片。
- 不使用完整 Dashboard 式面板網格。

## 各區段版面方向

### 1. 專案核心主張

- 不使用人物、裝置 Mockup、Notion App 截圖或抽象 AI 主視覺。
- 視覺重點由標題、6,186 則評論、資料範圍與版面留白建立。
- `6,186` 標示為「納入分析的有效評論」；原始蒐集量 `6,269` 不作為第一屏主數字。
- 可加入低對比資料欄位、批次編號或細網格作為結構背景，但不得影響文字閱讀。
- 第一屏不顯示 23 個批次、17 個主題或 645 筆 evidence。
- 第一屏不列出完整方法名稱；方法與目的移至下方的未編號導讀。

### 未編號導讀：分析思路

- 位於第一屏與「問題為什麼困難」之間，不增加第十一個導覽區段。
- 使用短標題、單段說明與三個水平步驟，交代資料清理、情緒分流與大型語言模型分析各自的用途。
- 三個步驟使用分隔線形成連續閱讀，不使用卡片、圖示或成果數字。
- 最後以一段左側細線文字帶入三個問題難點。
- 手機版改為單欄垂直排列，不允許橫向捲動。

### 2. 問題為什麼困難

- 三個難點使用連續且有編號的內容區塊。
- 不使用三張裝飾性卡片。
- 不在本區加入成果 KPI。

### 3. 整體分析流程

使用六階段編號資料流：

1. 資料準備。
2. 情緒分流。
3. 深入分析選樣。
4. 結構化主題分析。
5. 來源回查與稽核。
6. 主題整併。

設計規則：

- 每個階段最多一個主要數字。
- 階段之間使用清楚連線表達資料去向。
- 不使用漏斗圖，避免暗示每個階段都在淘汰資料。
- 不使用複雜系統架構圖作為第一層流程說明。
- 工具名稱放在次要位置。
- 手機版改成單欄垂直資料流。

### 4. 三項核心技術決策

- 以 01、02、03 編號形成連續內容。
- 每項依序顯示問題、決定、原因與限制。
- 限制不隱藏在 tooltip 或過小註解中。

### 5. 真實品質控制案例

採用深色技術區段。

桌面版：

- 左側顯示模型原始輸出。
- 右側顯示 `review_id` 對應的真實評論。
- 下方顯示問題判斷、移除結果與流程改善。

手機版：

- 模型輸出與真實來源改成上下排列。

色彩使用：

- 青綠表示可驗證來源與完成狀態。
- 琥珀色表示需要檢查的差異。
- 不使用紅色大叉、警報效果或誇張錯誤動畫。

### 6. 主要分析結果

三個主題垂直排列，不做競賽式排行榜。

每個主題包含：

- 主題序號與名稱。
- 中文分析摘要。
- 分析批次覆蓋數。
- 19 格批次覆蓋條。
- evidence 數。
- 兩則代表引文。
- 待驗證方向。

19 格批次覆蓋條：

- 每格代表一個負面或不確定分析批次。
- 顯示 19 / 19、18 / 19、17 / 19。
- 必須固定標示「代表主題出現在多少分析批次，不是評論發生率」。
- 手機版允許分成兩列，不可橫向捲動。

### 7. 正向價值補充

- 三個價值使用簡短連續內容，不做排行。
- 每個價值只顯示一則代表 evidence。
- 不和負面主題共用同一個比較圖表。
- 不使用綠色作為唯一正向辨識方式。

### 8. 延伸驗證設計

- 桌面版採左右配置：左側呈現五步驟監測方法，右側呈現目前實際資料狀態。
- 左側以簡潔步驟呈現 28 天前後觀察方法。
- 右側顯示 3 個候選案例、6 筆規則命中評論，以及目前保留為監測基線的狀態。
- 手機版先顯示監測方法，再顯示實際資料狀態。
- 左右摘要下方使用完整內容寬度呈現一個真實案例：固定時間切點、主題規則、前後 28 天比較、案例判定與實際命中評論。
- 前後比較使用表格，顯示可比較評論、規則命中與命中率；不使用趨勢圖。
- 案例來源使用原地展開，顯示完整評論與來源 metadata。
- 不顯示公開更新名稱，不把數字下降設計成改善成效。
- 「資料不足，保留為後續監測基線」以克制的狀態說明呈現，不作錯誤警報。

### 9. 工程交付與可重跑性

- 桌面版採左右配置：左側為精簡交付結構，右側為四項工程證據。
- 左側顯示 `configs/`、`src/analysis/`、`outputs/tables/`、`tests/` 與 `docs/methodology/` 的用途，不展開完整檔案樹。
- 右側呈現各階段可獨立執行、決策有版本紀錄、中間與最終產物保留，以及 59 項測試等可驗證事實。
- 手機版先呈現交付結構，再呈現四項工程證據。
- 使用實際產物、檔案名稱與驗證結果證明工程能力。
- 不使用技術 Logo 牆。
- 不貼大量程式碼。
- 不描述為一鍵重跑，除非後續真的實作並驗證完整流程編排。

### 10. 分析範圍、解讀邊界與後續方向

分成三段：

1. 目前已建立的分析基礎。
2. 解讀結果時需要注意。
3. 後續可補強方向。

- 三段上下排列，使用編輯式橫向內容，不做三張卡片。
- 前兩段沿用一般淺色背景；最後一段以低彩度淡綠背景收尾。
- 結尾重點放在可執行的後續補強方向，不停留在限制清單。
- 不使用「可以回答／不能回答」作為標題。

## Evidence 互動

採用「代表引文預設顯示，來源資訊原地展開」。

- 每個主要主題預設顯示兩則代表引文。
- 引文旁提供「查看來源」。
- 展開後顯示完整 `review_id`、日期、星等、App 版本與所屬分析批次。
- 每則引文獨立展開，允許同時開啟多則以利比較。
- 欄位缺少資料時顯示「資料未提供」，不留白或推測。
- 再次操作同一控制可收合來源資訊。
- 不使用彈出視窗，確保手機操作與閱讀順暢。
- 不預設載出 645 筆 evidence 清單。
- 不在第一版建立完整 evidence 搜尋 Dashboard。
- 未來若公開 repo，可提供正式 CSV 連結。

## 動態效果

採用低動態、以狀態回饋為主。

- 導覽標記隨目前章節更新。
- evidence 展開使用簡短且克制的過渡。
- 按鈕與連結提供清楚的 hover 與 focus 狀態。
- 尊重 `prefers-reduced-motion`。
- 不使用數字累加、打字機效果、視差、漂浮粒子或自動播放動畫。
- 19 格批次覆蓋直接顯示，不逐格播放。

## 圖像與裝飾

- 不使用裝飾性主視覺圖片。
- 不使用 AI 生成抽象圖。
- 不使用 Notion App 截圖作為主要內容。
- 不使用人物、裝置 Mockup 或無資料意義的圖示群。
- 視覺重點來自資料流、品質比較、批次覆蓋與原始 evidence。

## 可用性與無障礙

- 文字與背景需符合足夠對比度。
- 青綠與琥珀狀態必須同時搭配文字或形狀，不只依賴色彩。
- 所有展開控制可使用鍵盤操作。
- focus 狀態必須清楚可見。
- 行動裝置點擊區域需足夠。
- 引文與 metadata 使用正確語意結構。
- 導覽需支援跳至內容並避免固定導覽遮住標題。

## 前端資料整合

網站採用建置時產生、執行時靜態載入的資料架構，不需要 API、後端或資料庫。

- `portfolioSnapshot.json`：由 `outputs/tables/` 的分析產物產生，保存統計數字、主題覆蓋、代表 evidence 與來源 metadata。
- `portfolioContent.ts`：保存已確認的標題、說明、技術決策與解讀邊界。
- `portfolio.ts`：定義 TypeScript 資料型別。
- React 網站直接匯入上述靜態資料，不在瀏覽器執行分析或呼叫外部 API。
- 資料產生階段驗證關鍵數字、必要欄位與 evidence ID；驗證失敗時停止建置。
- 建立新版作品集專用資料格式，不沿用舊網頁的 Dashboard 資料結構或文案。

## 第一版公開範圍

- 第一版不提供 GitHub repository、完整評論檔或 645 筆 evidence 資料檔連結。
- 不放置尚未啟用的「查看原始碼」或「下載資料」按鈕。
- 網頁仍顯示實際交付結構、驗證結果與代表 evidence 的來源 metadata。
- 新版網站完成後，另行執行公開版本審查，再決定是否加入「查看實作」連結。
- 公開版本審查至少包含：舊網頁隔離、README 與執行說明、敏感設定檢查，以及原始評論資料的散布範圍。
